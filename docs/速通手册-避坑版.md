# 米家设备接入速通手册（避坑版 v2）

> 目标：让"豆包工作 → Home Assistant → 米家设备"链路在任何一台新机器上最短时间跑通。
> 首次实装 ≈ 2 小时（本次实际），按本手册复刻 ≈ 15–25 分钟（估算）。
> 适用范围：Linux（无 sudo/docker）与 macOS 通用；GUI 自动化基于 browser-use / computer-use。

---

## 0. 动手前先锁定（本次最大的弯路）

- [ ] 确定**主战场**：哪台机器长期跑 HA？（本次先 Mac 后云电脑，双轨重复建设 ≈ 40% 耗时）
- [ ] 确定授权方式：账号+密码（需短信验证码）或扫码
- [ ] 确定令牌落盘路径（建议 `~/hass/HA_TOKEN.txt`，**不要放进会被云同步的技能目录**）

> 经验：两台机器都装时，先在一台完整跑通，第二台**复制授权产物**（见 §5），不要重走 OAuth。

---

## 1. 运行时（免编译，防编译坑）

```bash
# uv 装预编译 Python（Mac 沙箱 Python / 系统 Python 缺头文件会导致 assist_pipeline 编译失败、前端卡死）
uv python install 3.14
uv venv --python 3.14 ~/hass/.venv
```

坑：`pymicro-vad/pyspeex-noise` 编译失败 → `assist_pipeline` 组件 setup 失败 → 前端 SPA 卡死。用预编译版 Python 可完全避免。

## 2. 依赖一次装全（本次漏装 paho-mqtt）

```bash
uv pip install --python ~/hass/.venv/bin/python homeassistant
uv pip install --python ~/hass/.venv/bin/python paho-mqtt  # 关键！漏装则自定义集成不加载
# 小米官方集成 ha_xiaomi_home 依赖：construct≥2.10.56 / paho-mqtt / numpy / cryptography / psutil
```

坑：集成页搜 Xiaomi 只能看到内置 miio 直连版 = 自定义集成未加载，先查日志 `No module named 'paho'`。

## 3. onboarding（API 优先，GUI 只做必须）

```bash
# 启动
pkill -9 -f '[v]env/bin/hass'   # 方括号防自杀（裸写会匹配到 pkill 自身 exit 137）
nohup ~/hass/.venv/bin/hass -c ~/hass/config > ~/hass/hass.log 2>&1 &
# 等 60–90s 端口就绪
```

- POST `/api/onboarding/users` → 换 access_token → 配 country/language/time_zone + analytics(false)
- **坑**：integration 步 API 401（refresh_token invalid_grant）→ 直接改 `~/.storage/onboarding` 的 `done` 数组加 `"integration"`，重启生效

## 4. OAuth 授权（唯一必须走 GUI 的环节）

1. 浏览器 → 设置 → 集成 → 添加 → 搜 Xiaomi → **Xiaomi Home**（官方 OAuth 版，勿选 Xiaomi Gateway/ miio 直连）
2. 风险告知 → 基础配置（中国大陆 / 简体中文）→ 登录页走账号+密码 / 扫码
3. 安全手机验证码 → 授权跳转

**坑（本次 Mac/云电脑各踩一遍）**：回调 `http://homeassistant.local:8123/api/webhook/<id>?code=...` 无法解析 → 把 URL 中的 `homeassistant.local` 替换为 `127.0.0.1` 再访问，webhook 即收码成功。

授权成功标志：`~/hass/config/.storage/xiaomi_home/` 出现 `cert/xxx_cn.cert + .key`、`miot_config/xxx_cn.dict`（含 access_token）。

## 5. 第二台机器复用（跳过整个 OAuth）

```bash
# 把第一台的授权产物 + 令牌复制到第二台（同一小米账号）
cp -r ~/hass/config/.storage/xiaomi_home <第二台>/hass/config/.storage/
cp ~/hass/HA_TOKEN.txt <第二台>/hass/
```

无需重走小米登录/验证码/授权流程（OAuth 产物是设备级证书，直接复用）。

## 6. 长期令牌（GUI 创建，只显示一次）

- 用户资料 → 安全 → 长期访问令牌 → 创建令牌 → 命名 → 确定
- **坑**：弹窗输入框在 shadow DOM，`document.querySelector` 找不到（count=0）
  - 解法：`bu.snapshot()` 找到 `input[type=text]` 的 ref（如 `d9:e9`），用 `bu.type(ref, 名称)` 输入
  - 令牌只显示一次，创建后立即用 `bu.text(ref)` 读取完整 JWT（183 字符）并落盘

## 7. 技能脚本（一次成型，勿写"够用版"）

- `control.py` 要点（以当前线上版为模板）：
  - **别名表**：设备中文名 → 实体 ID 直连（快，0.1s 内）
  - **停用词归一化**：`normalize()` 去掉"的/在/把/帮我/打开…"，支持"客厅的空调"
  - **域优先级过滤**：模糊匹配优先 light/switch/humidifier/climate 等可控制域，过滤 button/sensor（本次踩坑：`states 加湿器` 命中 button 循环切换按钮）
  - **climate 两次调用**：`set_hvac_mode` 只传模式，`set_temperature` 单独传温度（合并会 400）
  - **light 兼容 on/off/亮度**，音箱走 `notify.*_execute_text_directive`（TTS 让音箱说话）
- SKILL.md 命令用法与脚本保持同步（本次补了 speaker 用法）

## 8. 开机自启 + 自动自检

```bash
crontab -l | grep -v hass ; echo '@reboot sleep 30 && /home/user/hass/.venv/bin/hass -c /home/user/hass/config >> /home/user/hass/hass.log 2>&1' | crontab -
```

自检清单（交付前逐项过）：
- [ ] `curl /api/` 返回 `API running.`
- [ ] 集成页 Xiaomi Home 显示设备数 = 16
- [ ] `control.py states "加湿器"` 命中 humidifier 实体
- [ ] 真实控制一次（on/off），**结束恢复设备原状态**
- [ ] 音箱 TTS 播报一句验证
- [ ] 设备状态快照与测试前一致
